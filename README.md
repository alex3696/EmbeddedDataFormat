## 1. Введение и мотивация

**EDF** — блочный бинарный формат для хранения структурированных данных в embedded-системах с ограниченными ресурсами. Предназначен для записи, хранения и передачи данных во flash/EEPROM микроконтроллеров, ведения логов и обмена между embedded-устройствами и ПК.

Формат создавался как простая бинарная альтернатива LAS и CSV, но с явным встроенным описанием схем, поддержкой вложенных структур и массивов. Похожие форматы: LAS, CSV, JSON, Protobuf, MessagePack, CBOR, TLV.

## Область применения

- Хранение результатов измерений различных датчиков в ограниченном объёме памяти
- Формат обмена/архивации для автономных и маломощных систем
- Хранение табличных данных во flash/EEPROM
- Обмен структурированными данными между embedded-устройствами и ПК
- Логирование (телеметрия устройств, события)

## Главные принципы и ограничения

- **Блочность:** Всё хранится и передаётся бинарными блоками. Размер: 256…4096 байт.
- **Контроль целостности (CRC16 Modbus):** В бинарном режиме, на каждый блок.
- **Восстановление:** Возможность восстановления последовательности при повреждении блоков.
- **Append-only:** Запись только с добавлением, идеально для flash-памяти/журналов.
- **Метаданные внутри:** Явная (встроенная) схема сериализуется перед данными.
- **Расширяемость:** Поддержка пользовательских структур и многомерных массивов.
- **Без malloc:** Только статические и линейные аллокаторы.
- **Little Endian:** Предназначено только для Little-endian платформ.
- **Строки:** Только UTF-8, максимум 255 байт (обрезка без предупреждения).
- **Простая реализация:** Для удобства портирования на любой язык.
- **Текстовое представление:** Для отладки и просмотра данных.

## Структура файла и блоков

### Таблица типов блоков

| Название   | Код (dec/hex) | Символ | Текстовый вид | Назначение             |
|------------|---------------|--------|---------------|------------------------|
| Конфиг     | 126 / 0x7E    | `~`    | `<~ ... >`    | Конфигурация файла     |
| Схема      | 63  / 0x3F    | `?`    | `<? ... >`    | Определение схемы      |
| Данные     | 61  / 0x3D    | `=`    | `<= ... >`    | Пользовательские данные|

### Общая структура блока (EdfBlock_t)

| Поле    | Размер    | Описание                               |
|---------|-----------|----------------------------------------|
| Type    | 1         | Тип блока                              |
| Len     | 2         | Длина Content                          |
| Content | [Len]     | Полезная нагрузка                      |
| CRC     | 2         | CRC16 (Modbus) от (Type+Len+Content)   |

- Каждый блок завершается CRC16.
- В текстовом режиме CRC отсутствует, блок завершается символом `>`

### Конфигурационный блок - EdfConfig_t

**Первый блок в EDF-файле, задаёт глобальные параметры.**

| Поле      | Тип      | Описание                 |
|-----------|----------|--------------------------|
| VersMajor | uint8_t  | Главная версия формата   |
| VersMinor | uint8_t  | Минорная версия формата  |
| Encoding  | uint16_t | Кодировка (только 65001) |
| Blocksize | uint16_t | Размер блока (256–4096)  |
| Reserved  | uint16_t | Зарезервировано (0)      |
| Flags     | uint32_t | Зарезервировано (0)      |

**Пример:** бинарный вид

| Type | Len   | Content                            | CRC  |
|------|-------|------------------------------------|------|
| 7E   | 0C 00 | 00 03 E9 FD 00 02 00 00 00 00 00 00|16 FA |

**Текущая версия:** 0.3

**Пример текстового блока конфига:**
```
//Edf Config: VersMajor; VersMinor; Blocksize; Encoding; Flags
<~{0;3;256;65001;0;}>
```

### Блок схемы (Schema–block)

**Содержит описание структуры пользовательских данных. Схема сериализуется полностью в один блок.**

- Размер схемы и записи не может превышать Blocksize.
- Максимум 255 полей в одной структуре (uint8_t)
- Общее число примитивов в структуре (включая вложенные и массивы) ≤ 65535

#### Формат EdfSchema_t:

| Поле       | Размер (байт)   | Описание                                            |
|------------|-----------------|-----------------------------------------------------|
| Id         | 2               | Идентификатор схемы (0…65535)                       |
| Name       | 1+N             | Имя схемы (byte length + bytes, ≤255)               |
| Desc       | 1+M             | Описание схемы (опционально, как строка)            |
| Type       | переменный      | Cостав поля (см. EdfType_t, рекурсивно)             |

#### Формат EdfType_t:

| Поле        | Размер (байт)    | Описание                                                        |
|-------------|------------------|-----------------------------------------------------------------|
| Type        | 1                | Примитивный или составной тип , см. PoType                      |
| DimsCount   | 1                | Кол-во измерений массива (0–255)                                |
| Dims        | DimsCount×2      | Размеры измерений (uint16_t)                                    |
| Name        | 1+N              | Имя типа/поля (строка)                                          |
| FieldsCount | 1 or отсутствует | Число полей (Struct) **Только если Type==Struct и FieldsCount>0**|
| Fields      | переменный       | (FieldsCount × EdfType_t)                                       |

**Примечания:**
- FieldsCount есть ТОЛЬКО если Type==Struct и FieldsCount>0
- Поля структуры хранятся строго в порядке объявления
- Максимум 255 полей в одной структуре (uint8_t)
- Общее число примитивов в структуре (включая вложенные и массивы) ≤ 65535

#### Полная таблица примитивных типов PoType

| Название | Код | Размер (байт) | C-тип      | Примечание                                       |
|----------|-----|---------------|------------|--------------------------------------------------|
| Struct   | 0   | –             | –          | Вложенная структура                              |
| Char     | 1   | 1             | char[N]    | Фиксированный массив ≤255 байт                   |
| Int8     | 2   | 1             | int8_t     |                                                  |
| UInt8    | 3   | 1             | uint8_t    |                                                  |
| Int16    | 4   | 2             | int16_t    |                                                  |
| UInt16   | 5   | 2             | uint16_t   |                                                  |
| Int32    | 6   | 4             | int32_t    |                                                  |
| UInt32   | 7   | 4             | uint32_t   |                                                  |
| Int64    | 8   | 8             | int64_t    |                                                  |
| UInt64   | 9   | 8             | uint64_t   |                                                  |
| Half     | 10  | 2             | uint16_t   | 16-bit float (IEEE 754-2008)                     |
| Single   | 11  | 4             | float      |                                                  |
| Double   | 12  | 8             | double     |                                                  |
| String   | 13  | 1+N           | char*      | Len (1 байт) + Data (≤255 байт, без '\0')       |

**Примечания:**
- **Char** — используется для строк фиксированной длины (char[10]). Хранится как сырые байты, пустые элементы в конце дополняются '\0'.
- **String** — динамическая строка, в бинарном виде имеет префикс длины (1 байт).
- **Строки** — обрезаются до 255 байт **БЕЗ предупреждения**.

**Пример текстового блока схемы:**
```
<? {0;"SensorData"} Struct {
  UInt32 "timestamp";
  Single "value";
  String "unit";
} >
```
**Пример бинарного блока схемы:**
```
3F 											// BlockType
33 											// BlockLen 51dec
00 00										// Id
0A 'S' 'e' 'n' 's' 'o' 'r' 'D' 'a' 't' 'a'	// Name
00											// Desc
00											// Type Struct
00											// Dims
06 'S' 'e' 'n' 's' 'o' 'r'					// Struct Name
03											// Fields
07 00 09 't' 'i' 'm' 'e' 's' 't' 'a' 'm' 'p'// Field0
0B 00 05 'v' 'a' 'l' 'u' 'e'				// Field1
0D 00 04 'u' 'n' 'i' 't'					// Field2
AB CD 										// BlockCrc sample CRC16
```

> **Важно:** После записи блока схемы через `EdfWriteSchema()` состояние контекста автоматически сбрасывается:
> - `SchId` устанавливается в соответствии с переданной схемой
> - `PrimOffset` и `RecordId` обнуляются
> - Счетчик длины блока данных сбрасывается

Это гарантирует, что следующие вызовы `EdfWriteData` будут начинать новую последовательность записей с корректными заголовками.

### Блок данных (Data–block)

**Содержит данные пользователя, сериализованные по конкретной схеме.**

#### Формат EdfRecordContent_t:

| Поле      | Размер            | Описание                                                            |
|-----------|-------------------|---------------------------------------------------------------------|
| SchId     | 2 (uint16_t)      | Идентификатор схемы, к которой относятся данные                     |
| PrmOffset | 2 (uint16_t)      | Смещение по примитивам (для восстановления при разрыве блока)       |
| RecId     | 4 (uint32_t)      | Логический номер записи                                             |
| Data      | перем.            | Сериализованные значения согласно схеме                             |

**Пример бинарных данных для схемы SensorData:**
```
3D 			// BlockType 
13			// BlockLen 19dec
00 00       // SchId = 0
00 00       // PrmOffset = 0 (начало записи)
00 00 00 00 // RecId = 0
80 96 AD 65 // timestamp = 1700000000 (UInt32, little-endian)
00 00 BC 41 // value = 23.5 (float, little-endian)
02          // len = 2 (String prefix)
D0 C2       // 'Р' 'С' (°C в UTF-8)
AB CD 		// BlockCrc sample CRC16
```

**Правила сериализации:**
- Структуры раскладываются на примитивы рекурсивно
- Сериализация строго по порядку полей структуры
- Примитив **не может быть разорван** между блоками
- Массивы раскладываются row-major (построчно)

**Ограничения:**
- Размер блока данных не может превышать Blocksize
- Используйте `#pragma pack(push,1)` для всех структур в C

## API: функции работы с EDF

### C API (Основной)

```c
// ===== Инициализация =====
// Инициализирует контекст с существующей памятью
int EdfInit(EdfContext_t* ctx, uint8_t* mem, size_t memLen, const EdfConfig_t* cfg);

// Создает контекст и инициализирует его (удобно)
EdfContext_t* EdfCreate(uint8_t* mem, size_t memLen, const EdfConfig_t* cfg, int* pErr);

// ===== Открытие файлов/потоков =====
// Открывает поток для чтения/записи
// Режимы: "wb"/"rb" — бинарные, "wt"/"at" — текстовые, "ab" — дозапись
// ⚠️ ВАЖНО: Текстовое чтение ("rt") НЕ поддерживается (возвращает ERR_WRONG_PARAMETERS)
int EdfOpenStream(EdfContext_t* ctx, Stream_t* stream, const char* mode);
int EdfOpenFile(EdfContext_t* ctx, const char* fname, const char* mode);
int EdfOpenWithFs(EdfContext_t* ctx, const char* file, const char* mode, FileStreamOpenFn fnOpen);

// ===== Запись =====
int EdfWriteConfig(EdfContext_t* ctx, size_t* writed);        // Запись конфигурации
int EdfWriteSchema(EdfContext_t* ctx, const EdfSchema_t* sch, size_t* writed);  // Запись схемы
int EdfWriteData(EdfContext_t* ctx, const void* data, size_t len);  // Запись данных
int EdfFlushData(EdfContext_t* ctx, size_t* writed);          // Закрытие текущего блока

// Shortcut функции
int EdfWriteSchemaData(EdfContext_t* ctx, const EdfSchema_t* ir, const void* d, size_t len);
int EdfWritePrimSchData(EdfContext_t* ctx, PoType pt, uint16_t schId, char* schName, char* schDesc, const void* d);

// ===== Чтение =====
int EdfReadBlock(EdfContext_t* ctx);  // Чтение блока из потока
int EdfReadBin(const EdfType_t* t, MemStream_t* src, LineAlloc_t* mem, 
               void** presult, size_t* resultPrimOffset, size_t* primReaded);

// ===== Завершение =====
int EdfClose(EdfContext_t* ctx);  // Закрытие и освобождение ресурсов
```

**Передача данных примитивных типов:**
```c
int32_t val = 123;
EdfWriteData(ctx, &val, sizeof(val), NULL);
```

**Передача строк:**
```c
const char* str = "hello";
EdfWriteData(ctx, &str, sizeof(char*), NULL);
```

## Примеры использования

### Пример 1: Базовая запись данных (C)

```c
#pragma pack(push,1)
typedef struct
{
    uint32_t timestamp;
    float value;
    char unit[10];
} SensorData_t;
#pragma pack(pop)

int main()
{
    int err = 0;
    uint8_t edfMem[MEM_BLOCK_SIZE_256] = {0};
    EdfContext_t* ctx = EdfCreate(edfMem, sizeof(edfMem), &EdfCfg256, &err);
    
    // Определяем схему
    EdfSchema_t schema = {
        .Id = 0,
        .Name = "SensorData",
        .Type = {
            .Type = Struct,
            .Fields = {
                .Count = 3,
                .Item = (EdfType_t[]) {
                    { UInt32, "timestamp" },
                    { Single, "value" },
                    { Char, "unit", .Dims = {1, (uint16_t[]){10}} },
                }
            }
        }
    };
    
    // Открываем файл и пишем
    if ((err = EdfOpenFile(ctx, "output.bdf", "wb")))
        return err;
    if ((err = EdfWriteConfig(ctx, NULL)))
        return err;
    if ((err = EdfWriteSchema(ctx, &schema, NULL)))
        return err;
    
    // Записываем данные
    SensorData_t data[] = {
        {1700000000, 23.5, "°C"},
        {1700000060, 23.6, "°C"}
    };
    
    for (int i = 0; i < 2; i++) {
        if ((err = EdfWriteData(ctx, &data[i], sizeof(SensorData_t), NULL)))
            return err;
    }
    
    EdfClose(ctx);
    return 0;
}
```

### Пример 2: Чтение данных (C)

```c
int err = 0;
uint8_t edfMem[MEM_BLOCK_SIZE_256] = {0};
EdfContext_t* ctx = EdfCreate(edfMem, sizeof(edfMem), &EdfCfg256, &err);

if ((err = EdfOpenFile(ctx, "output.bdf", "rb")))
    return err;

int record_count = 0;
while ((err = EdfReadBlock(ctx)) == ERR_NO)
{
    if (ctx->Blk->Type == btData)
    {
        // Открываем поток для чтения данных в блоке
        MemStream_t dataStream = {0};
        MemStreamReadOpen(&dataStream, ctx->Blk->Content.Record.Data, 
                         GetContentDataLen(ctx->Blk));
        
        // Выделяем память для результатов
        uint8_t buffer[1024] = {0};
        LineAlloc_t mem = {0};
        LineAllocInit(&mem, buffer, sizeof(buffer));
        
        // Читаем записи используя схему
        SensorData_t* data = NULL;
        size_t primOffset = 0, primRead = 0;
        
        if ((err = EdfReadBin(&ctx->SchemaPtr->Type, &dataStream, &mem, 
                             (void**)&data, &primOffset, &primRead)) == ERR_NO)
        {
            printf("Record %d: ts=%u, val=%.1f, unit=%s\n", 
                   record_count++, data->timestamp, data->value, data->unit);
        }
    }
}

if (err == ERR_EOF)
    err = 0;  // Normal end

EdfClose(ctx);
```

### ⚠️ Критические замечания

#### 1. Безопасность строк

**Строки обрезаются до 255 байт БЕЗ предупреждения!**

```c
// Опасно: строка будет молча обрезана
const char* longStr = "очень длинная строка..."; // >255 байт
EdfWriteData(ctx, &longStr, sizeof(char*), NULL);  // Только первые 255 байт
```

**Рекомендация:** Проверяйте длину перед записью:
```c
size_t len = strlen(myString);
if (len > 255) {
    fprintf(stderr, "String too long: %zu bytes (max 255)\n", len);
    return ERR_WRONG_PARAMETERS;
}
```

#### 2. Кэширование схемы в контексте

**После `EdfWriteSchema()` контекст кэширует указатель на схему! **

```c
// ✅ Правильно: схема — статическая
static const EdfSchema_t schema = {...};
EdfWriteSchema(ctx, &schema, NULL);

// ❌ ОПАСНО: Undefined behavior
{
    EdfSchema_t localSchema = {...};
    EdfWriteSchema(ctx, &localSchema, NULL);
    // localSchema удалена, ctx->SchemaPtr указывает на мусор!
}
```

**Правило:** Гарантируйте, что схема остаётся в памяти на весь сеанс записи.
пока сойдёт и так, но в будущем будет исправлено

#### 3. Многопоточность

⚠️ **Объекты `EdfContext`, `EdfBinaryWriter`, `EdfBinaryReader` НЕ thread-safe!**
- по определению, т.к. последовательная запись/чтение примитивов и блоков

#### 4. Текстовое чтение НЕ поддерживается

```c
// ❌ Вернет ERR_WRONG_PARAMETERS
EdfOpenFile(ctx, "file.tdf", "rt");

// ✅ Поддерживается: текстовая запись
EdfOpenFile(ctx, "file.tdf", "wt");

// Для текстового чтения используйте C#
```

### Выбор размера блока

| Размер | Применение | Плюсы | Минусы |
|--------|------------|-------|--------|
| 256    | Микроконтроллеры, минимальная память | Экономия памяти | Больше служебных данных |
| 512    | Типичные embedded системы | Баланс | — |
| 1024   | Схстемы с достатком памяти | Хорошая компактность | Больше требований к памяти |
| 2048-4096 | ПК, высокопроизводительность | Максимальная компактность | Значительное требование памяти |

**Правило:** Больший блок = лучшая компактность (% служебных данных мал). Меньший блок = меньше требований к памяти.

### Версионирование

EDF использует семантическое версионирование (Major.Minor):
- **Текущая версия:** 0.3
- **Major версия**: изменение при несовместимости формата
- **Minor версия**: изменение при добавлении новых типов или функций

**Проверяйте версию при открытии:**
```c
if (config.VersMajor != EDF_VERSMAJOR) {
    fprintf(stderr, "Incompatible version: %d.%d\n", 
            config.VersMajor, config.VersMinor);
    return ERR_WRONG_PARAMETERS;
}
```

### Конвертер cedf.exe

```bash
cedf.exe <source> <target> <format>

Примеры:
  cedf.exe 1D.D 1D.tdf t       # динамограмма → текстовый
  cedf.exe 1D.D 1D.bdf b       # динамограмма → бинарный
  cedf.exe 1E.E 1E.bdf b       # эхограмма → бинарный
  cedf.exe 1DAT.DAT 1DAT.bdf b # манометр → бинарный
  cedf.exe 1DAT.bdf 1DAT.DAT d # бинарный → манометр
```

**Форматы файлов:**

- `*.bdf` — **основное представление** (Binary Data Format)
  - Компактное бинарное хранение
  - Оптимально для долгосрочной архивации и flash-памяти
  - Включает схему и CRC16-контроль

- `*.tdf` — **текстовое представление** (Text Data Format)
  - Человекочитаемое дополнение к .bdf
  - Идентично по содержимому соответствующему .bdf
  - Для отладки, диффа и интеграции со скриптами

## FAQ

**Q: Можно ли смешивать записи разных схем вперемежку?**
**A:** Нет! Data-блоки каждого типа идут строго после своей Schema. Смешивание Data разных схем приведет к ошибке при чтении.

**Q: Как восстановить поток после потери блока?**
**A:** Используйте SchId, PrmOffset, RecId для правильного пропуска и восстановления последовательности при сбое.

**Q: Что произойдёт, если схема не помещается в блок?**
**A:** Вернётся ошибка ERR_DST_SHORT или ERR_BLOCK_SIZE_LARGE.

**Q: Почему строки ограничены 255 байтами?**
**A:** Ограничение сделано для компактности (1 байт на длину String). Для очень длинных текстов используйте несколько записей или отдельный файл со ссылкой.

**Q: Поддерживает ли EDF Nullable/Optional типы?**
**A:** В C — нет встроенной поддержки. В .NET — используйте `T?` с `[EdfSerializable]` атрибутом для автогенерации.

**Q: Как выбрать размер блока?**
**A:** См. таблицу выше. Рекомендация: 256 (микроконтроллеры) или 512 (стандарт).

**Q: Работает ли EDF с Big-Endian?**
**A:** Нет, предназначен только для Little-Endian платформ (современный стандарт).
